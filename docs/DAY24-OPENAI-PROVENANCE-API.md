## Official API contract reviewed 23 October 2026

- Endpoint: `POST https://api.openai.com/v1/content_provenance_checks`
- Authentication: `Authorization: Bearer $OPENAI_API_KEY`
- Body: one multipart `file` field; supported image types are PNG, JPEG, and WebP.
- Maximum documented file size: 50 MiB. This app deliberately retains its stricter 5 MiB limit.
- Response object: `content_provenance_check`, with a `results` array. Applicable image signals include `c2pa` and `synthid`; each has its own `outcome`. C2PA can include `validation_state`, `issuer`, `model`, and `generated_at`.
- Documented errors include 400 for malformed/unsupported/blocked files, 404 when the organization lacks access, and 429 for rate limiting.
- The API is synchronous; it does not require a job/polling flow.

Official sources:
- Guide: https://developers.openai.com/api/docs/guides/content-provenance
- API reference: https://developers.openai.com/api/reference/cli/resources/content_provenance_checks/methods/create
- Provenance and privacy information: https://help.openai.com/en/articles/8912793-provenance-signals-in-openai-generated-content

## Access, cost, and suitability

The official Help Center currently describes Content Provenance API checks as free under default usage limits. Higher limits are reviewed for qualifying public-interest provenance and information-integrity use cases. General commercial fraud-prevention/authentication use and resale are outside the described higher-limit program. Do not assume an increased quota or approval.

This is a provenance check for supported OpenAI signals, not a general AI-image detector. A `not_detected` result means only that supported signals were not found. It must not be presented as proof that an image is human-created or as a reliable negative for images generated by other vendors.

## Privacy and temporary-file policy

- Keep `ENABLE_EXTERNAL_PROVENANCE=false` unless an explicit deployment decision authorizes external processing.
- Do not connect the provider to `public/upload.php` until privacy disclosure, user expectations, access, quota, and error handling have been reviewed.
- When integration is approved, send only the already-validated temporary file. Do not copy it to MySQL, permanent storage, logs, or debugging artifacts.
- Delete the temporary upload in a `finally` path after analysis, including when the provider is disabled, times out, rejects the file, or returns malformed JSON.
- Do not log API keys, image bytes, or raw provider response bodies.
- OpenAI states that files submitted for provenance checks are processed for the check and are not stored unless legally required, nor used to train its models. The application should still minimize transfer and clearly disclose the external request.

## Existing repository status

- `OpenAIProvenanceProvider.php` uses the documented endpoint, bearer authentication, multipart `file`, disabled-by-default feature flag, fixed destination, TLS verification, timeouts, and a bounded response body.
- `OpenAIProvenanceResponseMapper.php` maps C2PA and SynthID outcomes separately.
- The provider is **not connected to the upload flow**. No real request or access check was performed.
- Current upload policy remains temporary processing; no original image retention.
- Raw PHP + Ubuntu 24.04 + Apache + MySQL in one Docker container; Dockerfile only; no Docker Compose.
- SonarCloud remains pending.
